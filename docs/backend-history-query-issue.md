# 历史记录查询问题

## 问题描述

前端保存历史记录时使用的是中文字段名（`'上班时间'`、`'下班时间'`），保存API返回成功，但查询时后端只返回了 `daily_report` 类型的记录，没有返回出勤时间相关的记录。

## 问题现象

### 1. 保存历史记录（成功）

前端调用 `POST /api/attendance/history` 保存历史记录：

```json
{
  "leaderId": "leader_u3ks16",
  "department": "smt02线",
  "memberId": "member_p72b9b",
  "memberName": "l",
  "field": "上班时间",
  "oldValue": "08:00",
  "newValue": "04:30",
  "changedBy": "leader_u3ks16",
  "changedAt": "2025-11-20T05:43:38.651Z"
}
```

后端返回：
```json
{
  "historyId": "hist_qmyco0",
  "saved": true
}
```

**保存成功！**

### 2. 查询历史记录（问题）

前端调用 `GET /api/attendance/history`（管理员，不传leaderId参数）：

**后端返回的16条记录中，所有记录的 `field` 都是 `'daily_report'`，没有 `'上班时间'` 或 `'下班时间'` 的记录。**

## 后端需要检查的问题

### 1. 数据库查询逻辑

检查 `GET /api/attendance/history` 接口的实现：

- **是否只返回了 `daily_report` 类型的记录？**
- **是否有过滤条件导致出勤时间相关的记录被过滤掉？**
- **管理员查询时是否正确返回所有类型的记录？**

### 2. 数据库存储

检查数据库中是否真的保存了这些记录：

```sql
-- 查询所有历史记录
SELECT * FROM attendance_history ORDER BY changedAt DESC;

-- 查询出勤时间相关的记录
SELECT * FROM attendance_history WHERE field IN ('上班时间', '下班时间', 'startTime', 'endTime') ORDER BY changedAt DESC;

-- 查询特定组长的记录
SELECT * FROM attendance_history WHERE leaderId = 'leader_u3ks16' ORDER BY changedAt DESC;
```

### 3. 字段名映射

检查后端是否在保存或查询时转换了字段名：

- 前端保存时使用：`'上班时间'`、`'下班时间'`
- 后端可能转换成了：`'startTime'`、`'endTime'`
- 如果转换了，查询时也需要使用转换后的字段名

## 期望行为

### 管理员查询历史记录时：

1. **应该返回所有类型的记录**（包括 `daily_report`、`上班时间`、`下班时间` 等）
2. **不应该只返回 `daily_report` 类型的记录**
3. **应该返回所有组长的记录**（不传 `leaderId` 时）

### 前端过滤逻辑：

前端会在客户端过滤出勤时间相关的记录：
- 只显示 `field` 为 `'上班时间'`、`'下班时间'`、`'出勤时长'`、`'record'`、`'startTime'`、`'endTime'`、`'duration'` 的记录
- 排除 `'daily_report'` 类型的记录（这些记录在"缺勤汇总"中显示）

## 解决方案

### 方案1：修复后端查询逻辑

确保 `GET /api/attendance/history` 返回所有类型的记录，不进行类型过滤。

### 方案2：检查字段名映射

如果后端在保存时转换了字段名（如 `'上班时间'` → `'startTime'`），需要：
1. 在查询时也使用转换后的字段名
2. 或者在前端保存时使用英文字段名

### 方案3：添加查询参数

如果需要按类型过滤，可以添加 `field` 查询参数：
- `GET /api/attendance/history?field=上班时间` - 只查询上班时间记录
- `GET /api/attendance/history` - 查询所有记录

## 测试建议

1. **直接查询数据库**，确认出勤时间相关的记录是否已保存
2. **测试查询接口**，确认是否返回了所有类型的记录
3. **检查权限控制**，确认管理员查询时是否正确返回所有组长的记录

**这是后端问题**，不是前端问题。前端保存时使用的是 `'上班时间'` 和 `'下班时间'`，保存API返回成功，但查询时后端没有返回这些记录。

需要后端检查：
1. 数据库是否真的保存了这些记录
2. 查询接口是否正确返回了所有类型的记录
3. 是否有字段名映射或转换的问题
