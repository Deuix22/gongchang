# 提交时间时区处理修复（后端配合）

## 问题描述

前端发送的 `submittedAt` 字段存在时区问题，导致显示时间比实际时间晚8小时。

## 前端修改

前端已修改为发送 ISO 格式（UTC）的提交时间：
- 之前：`"2025-12-19 08:38"`（本地时间字符串，UTC+8）
- 现在：`"2025-12-19T00:38:00.000Z"`（ISO 格式，UTC）

## 后端需要配合

### 1. 接收格式

后端接收的 `submittedAt` 字段现在为 ISO 格式（UTC），例如：
```json
{
  "records": [...],
  "submittedAt": "2025-12-19T00:38:00.000Z"
}
```

### 2. 存储格式

建议后端：
- **存储时**：保持 ISO 格式（UTC），或转换为数据库的 Date/DateTime 类型
- **返回时**：返回 ISO 格式（UTC），不要转换为本地时间字符串

### 3. 返回格式示例

后端返回的出勤记录中，`submittedAt` 字段应该是：
```json
{
  "records": [
    {
      "memberId": "...",
      "startTime": "...",
      "endTime": "...",
      "submittedAt": "2025-12-19T00:38:00.000Z"  // ISO 格式（UTC）
    }
  ]
}
```

**不要**返回本地时间字符串格式，例如：
```json
{
  "submittedAt": "2025-12-19 08:38"  // ❌ 不要这样返回
}
```

### 4. 前端处理

前端会：
1. 接收 ISO 格式（UTC）的 `submittedAt`
2. 使用 `new Date(submittedAt)` 解析（自动转换为本地时间）
3. 显示为本地时间格式：`"2025-12-19 08:38"`（UTC+8）

## 验证

1. 前端发送：`"2025-12-19T00:38:00.000Z"`（UTC，对应本地时间 08:38）
2. 后端存储：ISO 格式或 Date 类型
3. 后端返回：`"2025-12-19T00:38:00.000Z"`（UTC）
4. 前端显示：`"2025-12-19 08:38"`（本地时间，UTC+8）

## 注意事项

- 如果后端当前返回的是本地时间字符串格式，需要修改为返回 ISO 格式
- 确保数据库存储时正确处理时区（建议存储 UTC 时间）
- 前端已经能够正确处理 ISO 格式，无需额外修改
