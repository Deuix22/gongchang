# 后端数据保留要求

## 概述

出勤报告系统需要能够根据日期范围查询和导出历史数据。为了确保数据的可用性和合规性，后端需要实现数据保留策略。

## 1. 数据保留要求

### 1.1 最小保留期限

- **出勤历史记录（attendance_history）**：**至少保留 2 个月（60 天）的数据**
- **出勤记录（attendance_records）**：**至少保留 2 个月（60 天）的数据**

### 1.2 数据保留策略

1. **自动清理**：
   - 建议实现定时任务，自动清理超过保留期限的数据
   - 清理前应记录日志，便于审计
   - 清理操作应在低峰期执行（如凌晨）

2. **保留期限计算**：
   - 基于记录的 `changedAt` 或 `submittedAt` 字段
   - 只删除超过 60 天的记录
   - 保留期限应从记录创建时间开始计算

3. **数据备份**：
   - 建议在清理前进行数据备份
   - 备份数据可以存储到冷存储（如对象存储）或归档数据库

## 2. 查询功能要求

### 2.1 日期范围查询

- **接口**: `GET /api/attendance/history`
- **查询参数**:
  - `start` (可选): 开始日期，格式：`YYYY-MM-DD`
  - `end` (可选): 结束日期，格式：`YYYY-MM-DD`
- **要求**:
  - 支持按日期范围查询历史记录
  - 如果只提供 `start`，返回从该日期到现在的所有记录
  - 如果只提供 `end`，返回从最早记录到该日期的所有记录
  - 如果同时提供 `start` 和 `end`，返回该日期范围内的记录
  - 如果不提供日期参数，返回所有可用的记录（受保留期限限制）

### 2.2 数据导出

- 管理员可以通过前端界面选择日期范围
- 导出功能会根据选择的日期范围查询数据
- 导出的文件名包含日期范围信息，便于识别

## 3. 前端实现

### 3.1 日期选择器

- 已实现开始日期和结束日期选择器
- 支持自定义日期范围查询
- 日期选择器限制：结束日期不能超过今天

### 3.2 导出功能

- 导出文件名包含查询的日期范围
- 格式示例：
  - `出勤汇总_2025-11-01_至_2025-12-01.xlsx`（有日期范围）
  - `出勤汇总_2025-11-01_起.xlsx`（只有开始日期）
  - `出勤汇总_至_2025-12-01.xlsx`（只有结束日期）
  - `出勤汇总_全部数据_2025-12-01.xlsx`（无日期范围）

### 3.3 数据查询逻辑

- 前端调用 `getHistory` API 时传递 `start` 和 `end` 参数
- 如果后端使用 `>= start AND < end` 的逻辑，前端会将结束日期加一天以确保包含结束日期当天的数据

## 4. 后端实现建议

### 4.1 数据库查询优化

```sql
-- 查询指定日期范围的历史记录
SELECT * FROM attendance_history 
WHERE changedAt >= :startDate 
  AND changedAt < :endDate
  AND field = 'daily_report'
ORDER BY changedAt DESC;

-- 查询最近 60 天的记录（用于验证保留期限）
SELECT COUNT(*) FROM attendance_history 
WHERE changedAt >= DATE_SUB(NOW(), INTERVAL 60 DAY);
```

### 4.2 数据清理任务

```javascript
// 伪代码示例
async function cleanupOldRecords() {
  const retentionDays = 60;
  const cutoffDate = new Date();
  cutoffDate.setDate(cutoffDate.getDate() - retentionDays);
  
  // 记录清理前的数据量
  const countBefore = await getRecordCount();
  
  // 清理超过保留期限的记录
  await deleteRecordsBefore(cutoffDate);
  
  // 记录清理后的数据量
  const countAfter = await getRecordCount();
  
  console.log(`数据清理完成：删除了 ${countBefore - countAfter} 条记录`);
}
```

### 4.3 数据保留验证

- 定期检查数据库中是否还有 60 天前的数据
- 如果发现超过保留期限的数据，记录警告日志
- 提供管理接口，允许管理员查看数据保留状态

## 5. 监控和告警

### 5.1 数据保留监控

- 监控数据库中记录的数量
- 监控最旧记录的日期
- 如果最旧记录超过保留期限，发送告警

### 5.2 查询性能监控

- 监控日期范围查询的响应时间
- 如果查询时间过长，考虑添加索引或优化查询逻辑
- 建议在 `changedAt` 字段上添加索引

### 6.1 功能测试

1. **日期范围查询测试**：
   - 测试只提供开始日期
   - 测试只提供结束日期
   - 测试同时提供开始和结束日期

2. **数据保留测试**：

   - 验证导出文件名是否正确
   - 验证导出数据是否完整

### 6.2 性能测试

## 7. 注意事项

1. **数据合规性**：
   - 根据实际业务需求，可能需要保留更长时间的数据
   - 建议与业务方确认数据保留期限

2. **数据恢复**：
   - 如果误删数据，可以从备份中恢复
   - 建议定期测试数据恢复流程

3. **用户通知**：
   - 如果数据即将过期，建议提前通知管理员
   - 提供数据导出功能，允许管理员在数据过期前导出
