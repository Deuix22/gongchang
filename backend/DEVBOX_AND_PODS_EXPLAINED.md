# DevBox 与 Pod 说明文档

## 一、DevBox 和应用的关系

### 什么是 DevBox？

**DevBox** 是一个**开发环境**，类似于一个云端的开发机器，用于：
- 📝 编写和编辑代码
- 🔨 构建 Docker 镜像
- 🧪 本地测试代码
- 📦 发布新版本到镜像仓库

### 什么是应用（itkc01）？

**应用（itkc01）** 是**生产环境**，用于：
- 🚀 运行生产服务
- 🌐 对外提供 API 服务
- 👥 服务真实用户

### 两者的关系

```
┌─────────────────┐         ┌─────────────────┐
│   DevBox        │         │   应用 itkc01    │
│  (开发环境)      │         │   (生产环境)      │
├─────────────────┤         ├─────────────────┤
│ • 编写代码       │         │ • 运行服务       │
│ • 构建镜像       │────────▶│ • 提供 API       │
│ • 测试功能       │  镜像   │ • 服务用户       │
│ • 发布版本       │         │                 │
└─────────────────┘         └─────────────────┘
```

**工作流程**：
1. 在 **DevBox** 中开发代码
2. 在 **DevBox** 中构建 Docker 镜像（如 `devbox:1.1`）
3. 将镜像推送到镜像仓库
4. **应用 itkc01** 使用新镜像运行生产服务

### 可以关闭 DevBox 吗？

**答案：可以！** ✅

**原因**：
- DevBox 和 itkc01 是**完全独立**的两个服务
- 应用 itkc01 运行的是**已构建好的镜像**，不依赖 DevBox
- 关闭 DevBox 不会影响生产环境的运行

**什么时候需要 DevBox**：
- ✅ 需要开发新功能时
- ✅ 需要修复 bug 时
- ✅ 需要构建新镜像时
- ✅ 需要测试代码时

**什么时候可以关闭 DevBox**：
- ✅ 代码已经部署完成
- ✅ 暂时不需要开发
- ✅ 想节省资源成本

**注意**：
- 关闭 DevBox 后，如果需要开发，需要重新启动
- DevBox 的 SSH 连接会断开，但代码不会丢失（如果已保存）

## 二、Pod 列表说明

### 什么是 Pod？

**Pod** 是 Kubernetes 中的最小运行单位，可以理解为：
- 🎯 **应用的运行实例**
- 📦 **一个容器（或一组容器）的运行环境**
- 🔄 **可以自动重启、扩缩容的最小单元**

### 为什么有两个 Pod？

这是 **Kubernetes 的滚动更新（Rolling Update）机制**：

```
时间线：
┌─────────────────────────────────────────┐
│ 旧 Pod (running)                        │
│ itkc01-656b956889-8vksd                 │
│ 状态: running                           │
│ 服务: 正在提供 API                       │
└─────────────────────────────────────────┘
              ↓ 更新镜像版本
┌─────────────────────────────────────────┐
│ 新 Pod (waiting)                        │
│ itkc01-7d5ff55cbf-6fksv                 │
│ 状态: waiting → starting → running       │
│ 服务: 准备替换旧 Pod                     │
└─────────────────────────────────────────┘
              ↓ 新 Pod 启动成功
┌─────────────────────────────────────────┐
│ 旧 Pod (terminating)                    │
│ itkc01-656b956889-8vksd                 │
│ 状态: terminating                        │
│ 服务: 停止，流量切换到新 Pod              │
└─────────────────────────────────────────┘
```

**滚动更新的好处**：
- ✅ **零停机时间**：新 Pod 启动后，流量才切换到新 Pod
- ✅ **平滑升级**：用户无感知
- ✅ **自动回滚**：如果新 Pod 启动失败，旧 Pod 继续运行

### Pod 状态说明

| 状态 | 含义 | 说明 |
|------|------|------|
| `running` | 运行中 | Pod 正常启动，服务可用 |
| `waiting` | 等待中 | Pod 正在启动或等待资源 |
| `pending` | 待调度 | Pod 等待 Kubernetes 分配节点 |
| `terminating` | 终止中 | Pod 正在关闭，停止服务 |
| `failed` | 失败 | Pod 启动失败，需要检查日志 |

### 当前情况分析

**正常情况**：
- ✅ 你刚刚更新了镜像版本（从 `devbox:1.0` 到 `devbox:1.1`）
- ✅ Kubernetes 正在执行滚动更新
- ✅ 新 Pod 正在启动（`waiting` 状态）
- ✅ 旧 Pod 仍在运行（`running` 状态），确保服务不中断

**接下来会发生什么**：
1. 新 Pod (`itkc01-7d5ff55cbf-6fksv`) 启动完成，状态变为 `running`
2. 流量切换到新 Pod
3. 旧 Pod (`itkc01-656b956889-8vksd`) 停止，状态变为 `terminating`
4. 最终只保留一个新 Pod 运行

**如果新 Pod 一直 `waiting`**：
- 可能是启动时间较长（正常，通常 1-2 分钟）
- 可能是资源不足
- 可能是镜像拉取失败
- 可以点击 Pod 的日志图标查看启动日志
